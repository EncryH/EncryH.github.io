개발일지 4를 쓴 게 5월 12일이었다. 그로부터 두 달 반이 지났다. 그 사이에 커밋이 86개 쌓였고, Comlapse는 "기능이 돌아가는 프로토타입"에서 "배포를 준비하는 앱"으로 바뀌었다.

# 1. 음성 인식 엔진을 갈아엎다 — Vosk에서 whisper.cpp로

개발일지 4에서 Vosk 기반 오프라인 음성 인식을 붙였다고 썼었다. 하지만 실제로 한국어 강의를 틀어놓고 써보니, Vosk의 한국어 인식률은 실용 수준에 못 미쳤다. 짧은 문장은 괜찮았지만 강의처럼 연속으로 말하면 누락이 심했다.

결국 음성 엔진을 통째로 바꿨다. 선택지는 `whisper.cpp`였다.

whisper.cpp는 OpenAI Whisper 모델을 C/C++로 포팅한 프로젝트다. Electron 앱에서 네이티브 바이너리로 실행하면 브라우저 WASM보다 훨씬 빠르고, 모델 크기에 따라 정확도를 조절할 수 있다.

문제는 단순히 "엔진을 바꾼다"가 아니었다. 완전히 새로운 파이프라인을 만들어야 했다.

```text
마이크 입력 → PCM 버퍼 → 세그먼트 분리 → whisper.cpp 실행 → 결과 병합 → UI 표시
```

실시간 전사를 위해 AudioWorklet에서 PCM 데이터를 캡처하고, 30초 단위로 세그먼트를 나눈 뒤, 각 세그먼트를 whisper.cpp에 넘겨 텍스트로 변환하는 구조를 만들었다. 중간에 무음이 감지되면 세그먼트를 더 빨리 닫아서 응답성을 높였다.

모델은 용도에 따라 두 개를 쓴다.

| 용도 | 모델 | CER | 처리 속도 |
| --- | --- | ---: | ---: |
| 실시간 전사 | Small Q5_1 | 6.22% | 1.59x |
| 종료 후 정밀 전사 | Large v3 Turbo Q5_0 | 3.31% | 0.84x |

CER(Character Error Rate)은 FLEURS 한국어 공개 데이터셋으로 직접 벤치마크를 돌려서 측정했다. 벤치마크 스크립트도 직접 만들었다. 혼자 개발하니까 "이 정도면 되겠지"가 아니라 숫자로 확인하고 싶었다.

# 2. 하드웨어를 읽는 음성 엔진

whisper.cpp를 붙이면서 가장 고민한 부분은, 모든 PC가 같은 사양이 아니라는 점이었다.

내 노트북은 AMD Ryzen 5000 계열 내장 GPU가 달려 있다. 이 환경에서는 Vulkan 백엔드로 GPU 가속을 쓸 수 있다. 하지만 다른 사용자의 PC는 NVIDIA일 수도, Intel일 수도, GPU가 아예 없을 수도 있다.

그래서 엔진이 실행 전에 하드웨어를 확인하도록 만들었다.

```text
CPU 논리 코어 수 → GPU 공급자 확인 → 전체/여유 메모리 → 실행 계획 결정
```

메모리가 충분하면 Large 모델, 부족하면 Small 모델. AMD GPU면 Vulkan, 그 외에는 CPU 폴백. 이런 정책을 `runtimePolicy.js`에 모아두고, 검증되지 않은 GPU 백엔드 팩은 아무리 바이너리가 있어도 자동으로 활성화되지 않도록 무결성 검증을 걸었다.

모델 파일과 whisper.cpp 바이너리는 SHA-256 체크섬으로 검증한다. 다운로드 과정에서 파일이 깨지거나 변조되면 실행 자체가 차단된다.

이 구조를 만들면서 느낀 건, 음성 인식 하나를 제대로 붙이려면 "모델을 돌리는 코드" 말고도 하드웨어 정책, 보안, 에러 복구, 메모리 관리까지 전부 직접 설계해야 한다는 것이었다.

# 3. AI가 세 개가 되다 — 멀티 프로바이더 스트리밍

개발일지 4에서는 AI 모델 선택 구조를 만들었다고 썼다. 그 뒤로 실제로 세 개 프로바이더를 모두 연결했다.

- **Gemini** — Google의 생성 AI. SSE 스트리밍을 가장 먼저 구현한 프로바이더.
- **OpenAI (GPT)** — ChatGPT 스타일의 응답 포맷에 맞춰 파싱.
- **Anthropic (Claude)** — 시스템 프롬프트 구조가 다른 부분을 분기 처리.

세 프로바이더를 모두 실시간 스트리밍으로 연결하면서, 대시보드 채팅 UI도 ChatGPT 스타일로 바꿨다. 답변이 한 글자씩 흘러나오고, 중간에 멈출 수 있는 Stop 버튼도 넣었다.

![Comlapse AI 채팅 — 공부 데이터 기반 질의와 모델 선택](/image/2026-07-27-Comlapse-dev-05/ai-chat.png)

```jsx
// 스트리밍 응답을 실시간으로 렌더링
onStreamChunk={(chunk) => {
  setMessages(prev => {
    const last = prev[prev.length - 1]
    return [...prev.slice(0, -1), { ...last, content: last.content + chunk }]
  })
}}
```

![Comlapse AI 채팅 사이드바 — 대화 기록과 고정 채팅](/image/2026-07-27-Comlapse-dev-05/ai-chat-sidebar.png)

혼자 개발하면서 세 개의 AI API를 동시에 관리하는 건 생각보다 번거로웠다. 각 프로바이더마다 인증 방식, 요청 포맷, 스트리밍 프로토콜, 에러 응답 구조가 전부 다르다. 하지만 사용자 입장에서는 "어떤 AI든 같은 UI에서 쓸 수 있어야 한다"는 게 맞으니까, `operatorApi.js`에서 프로바이더별 차이를 흡수하는 통합 레이어를 만들었다.

# 4. 미니 AI 작업창 — Ctrl 더블탭의 비밀

Comlapse를 쓰다 보면, 공부하면서 갑자기 뭔가 궁금해질 때가 있다. 그때 앱을 전환하는 건 흐름이 끊긴다. 그래서 미니 AI 작업창을 만들었다.

Ctrl 키를 빠르게 두 번 누르면 화면 오른쪽 아래에 작은 플로팅 창이 뜬다. 이 창에서 바로 AI에게 질문할 수 있고, 현재 화면을 캡처해서 "이 화면에서 뭘 하고 있는지" 분석을 요청할 수도 있다.

Ctrl 더블탭 감지는 Windows API를 직접 호출해서 구현했다. `koffi` 라이브러리로 `GetAsyncKeyState`를 폴링하는 방식이다. Electron의 글로벌 단축키로는 "더블탭" 같은 제스처를 잡을 수 없어서, 네이티브 레벨로 내려가야 했다.

미니 창은 항상 최상위에 뜨고, 다른 앱 위에 겹쳐진다. 다시 Ctrl 더블탭을 누르면 사라진다. 마치 macOS의 Spotlight 같은 느낌을 Windows 데스크톱 앱에서 구현한 셈이다.

이 기능을 만들면서 Electron이 "웹앱을 감싼 껍데기"가 아니라 실제 운영체제와 깊이 연결된 플랫폼이라는 걸 체감했다.

# 5. 인증과 플랜 — Supabase로 사용자를 다루다

혼자 쓰는 앱에서 여러 사람이 쓸 수 있는 앱으로 바꾸려면 인증이 필요했다.

처음에는 딥 링크 방식(`comlapse://auth/callback`)으로 인증을 구현했다. 외부 브라우저에서 로그인한 뒤 딥 링크로 앱에 토큰을 전달하는 구조였는데, Windows에서 프로토콜 핸들러 등록이 불안정한 경우가 있었다. 결국 앱 내부에 로그인 창을 띄우고 `localStorage`에서 세션을 추출하는 방식으로 바꿨다.

Supabase를 선택한 이유는 간단하다. 무료 플랜으로 인증과 데이터베이스를 모두 쓸 수 있고, 구독 정보를 조회해서 플랜별 기능 제한을 걸 수 있다.

```js
// 플랜에 따라 기능 접근 제어
const plan = await getPlanFromSubscription(user.id)
if (plan === 'free' && feature === 'ai-unlimited') {
  return { allowed: false, reason: 'Pro 플랜이 필요합니다' }
}
```

인증과 과금은 1인 개발에서 가장 하기 싫은 부분이었다. 코드를 짜는 게 아니라 "비즈니스 로직"을 짜는 느낌이라, 기능 개발과는 다른 종류의 피로가 있었다.

# 6. 보안, 구조 정리, 그리고 눈에 안 보이는 작업들

기능만 추가한 두 달은 아니었다. 오히려 눈에 안 보이는 작업이 더 많았다.

AI 기능이 늘면서 프롬프트 인젝션 방어, IPC 채널 화이트리스트, 파일 경로 검증, API 키 암호화 저장 같은 보안 계층을 하나씩 쌓았다. 보안은 "나중에 하자"고 미루면 한꺼번에 고치기가 훨씬 어렵다는 걸 배웠다.

`App.css` 하나에 수천 줄이 들어 있던 스타일도 12개 파일로 쪼갰고, React 컴포넌트도 기능별 폴더로 나눴다. 다크 모드만 있던 테마에 라이트 모드를 추가하면서 색상을 하나하나 다시 잡았다. 디자이너 없이 혼자 "이게 자연스러운가?"를 판단하는 건 생각보다 지치는 일이었다.

장시간 녹화 시 메모리가 쌓이는 문제도 있었다. 녹화 청크를 디스크로 즉시 내려보내고, 음성 PCM 세그먼트의 수명을 제한하는 식으로 해결했다. 이런 건 5분짜리 테스트에서는 절대 안 나오고, 실제로 1시간 강의를 틀어놓고 돌려봐야 보인다.

# 7. 대시보드 재설계

대시보드를 완전히 다시 만들었다. 기록 전에는 자료 추가 영역과 하단 컨트롤바가 중심이고, 기록 중에는 화면 미리보기, 메모장, 음성/요약/퀴즈/채팅 패널로 전환된다. 컨트롤바 한 줄에 기록 상태, 녹화 대상, 음성 설정을 담으면서도 복잡해 보이지 않게 만드는 데 시간을 많이 썼다.

# 8. 혼자 개발하면서 느낀 것

두 달 반 동안 혼자 이 앱을 만들면서 몇 가지를 느꼈다.

**결정의 속도가 빨라진다.** 디자인 리뷰, 코드 리뷰, 기술 선택 회의 같은 과정이 없다. Vosk가 안 되면 바로 whisper.cpp로 바꾸고, 딥 링크 인증이 불안정하면 바로 인앱 로그인으로 바꾼다. 이 속도는 1인 개발의 가장 큰 장점이다.

**하지만 실수도 혼자 책임진다.** 리뷰어가 없으니 보안 구멍을 직접 찾아야 하고, 디자이너가 없으니 UI 일관성을 직접 지켜야 한다. 테스트도 직접 하고, 문서도 직접 쓴다. 한 사람이 아키텍트, 프론트엔드, 백엔드, DevOps, QA, 디자이너를 동시에 하는 셈이다.

**기록의 중요성.** `PROJECT_CONTEXT.md`, `TODO.md`, `AGENTS.md` 같은 문서를 유지하는 게 처음에는 번거로웠다. 하지만 일주일 쉬고 돌아왔을 때, 이 문서들이 없었다면 "지금 뭘 하고 있었지?"부터 다시 파악해야 했을 것이다. 1인 개발에서 문서는 미래의 나를 위한 온보딩 가이드다.

**완벽보다 완성.** 음성 인식 CER이 3%인지 5%인지보다, 사용자가 실제로 녹음 버튼을 누르고 나중에 그 내용을 다시 볼 수 있는지가 더 중요하다. 완벽한 엔진을 만들다 앱을 못 내는 것보다, 충분히 좋은 엔진으로 앱을 내는 게 낫다.

# 9. 현재 상태와 앞으로

지금 Comlapse는 이런 상태다.

- 화면 녹화, 음성 녹음, 실시간 전사가 하나의 세션으로 통합되어 동작한다
- whisper.cpp 기반 오프라인 한국어 음성 인식이 실시간과 정밀 모드로 동작한다
- Gemini, GPT, Claude 세 개 AI로 요약, 퀴즈, 채팅을 할 수 있다
- 세션 기록을 타임랩스로 복습하고, PDF 자료와 함께 볼 수 있다
- Supabase 인증과 플랜 기반 접근 제어가 동작한다
- Electron 보안 기준을 체계적으로 유지하고 있다
- Windows NSIS 설치 파일을 빌드할 수 있다

남은 과제:

- 음성 인식 첫 구간 지연 개선
- 장시간 녹음 안정성 테스트 마무리
- Windows 코드 서명 인증서 연결
- 오픈소스 라이선스 고지 정리
- NVIDIA CUDA, Intel OpenVINO 백엔드 검증

두 달 반 전에는 "오프라인에서 음성을 인식할 수 있을까?"를 고민했다. 지금은 "배포할 때 코드 서명을 어떻게 하지?"를 고민한다. 고민의 종류가 바뀌었다는 건, 그만큼 앱이 성장했다는 뜻이다.

Comlapse는 아직 버전 0.0.1이다. 하지만 이 버전 번호는 앱의 완성도가 아니라 아직 세상에 나가지 않았다는 표시일 뿐이다. 곧 나간다.

사실 Comlapse를 만든 이유는 단순하다. 내가 쓰려고 만들었다. 강의를 들으면서 화면을 녹화하고, 나중에 다시 보면서 정리하고, 궁금한 건 AI한테 바로 물어보는 — 그런 흐름이 하나의 앱 안에서 끊기지 않았으면 좋겠다고 생각했다. 기존에 있는 도구들을 조합하면 비슷하게 할 수는 있지만, 매번 앱을 오가는 게 싫었다.

2학기가 시작되면 본격적으로 쓸 생각이다. 전공 강의를 들으면서 실제로 Comlapse로 기록하고 복습하는 것이 목표다. 그때가 되면 지금까지 만든 기능들이 진짜로 쓸 만한지, 어디가 불편한지가 바로 드러날 것이다. 개발자가 아니라 사용자로서 내 앱을 쓰는 시간이 가장 정직한 테스트다.

결국 좋은 도구는 만든 사람이 매일 쓰는 도구라고 생각한다. 2학기에는 Comlapse가 그런 도구가 되기를 바란다.
